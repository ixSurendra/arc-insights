## Prerequisites

- **Bun** ≥ 1.1 (pinned to 1.1.34 in `.tool-versions`)
- **Docker** + Docker Compose
- **Make**

## One-time setup

```bash
git clone https://github.com/ixSurendra/arc-insights.git
cd arc-insights
bun install
```

## Boot everything

```bash
make dev
```

This starts:

- The Elysia API on **`:3000`** (health check at `/health`, Swagger UI at `/docs`)
- The React + Vite frontend on **`:5173`** (proxies `/v1` and `/health` to the API)
- **Postgres 16** on `:5432` (Docker Compose, named volume)
- **Valkey 7** on `:6379` (Docker Compose, ephemeral)

Open <http://localhost:5173> — you should see the live `/health` JSON rendered
through the Eden Treaty SDK. That confirms the typed client-server loop is alive.

## Apply the database migration

```bash
cd backend
bun run db:bootstrap
```

This creates the `tenants`, `users`, and `audit_log` tables, enables row-level
security, and sets up the non-superuser `app_user` role. See
[`docs/adr/0003-multi-tenancy-model.md`](https://github.com/ixSurendra/arc-insights/blob/main/docs/adr/0003-multi-tenancy-model.md)
for why every domain table looks like this.

## Run the test suite

```bash
DATABASE_URL=postgresql://arc:arc_dev@localhost:5432/arc_insights bun run --filter '*' test
```

This includes the cross-tenant adversarial RLS suite that proves the
isolation guarantees from ADR 0003 hold against an actual Postgres.
