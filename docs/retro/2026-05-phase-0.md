## What we learned the hard way

Things that surprised us in CI or runtime — captured here so we don't re-learn them in Phase 1.

1. **Eden Treaty 1.4.x mangles an empty `baseUrl`** — the URL builder turns `""` into `"https:"`, producing `https:/health`. The fix in `sdk/src/index.ts` defaults to `window.location.origin` in the browser. _Test of record:_ `frontend/e2e/health.spec.ts` would have caught this.
2. **Postgres `POSTGRES_USER` is a superuser** which bypasses RLS even with `FORCE ROW LEVEL SECURITY`. Without a non-superuser role, RLS is decorative. Fixed by `CREATE ROLE app_user NOLOGIN` + `SET LOCAL ROLE app_user` inside `withTenant()`.
3. **Vitest's default include glob (`**/\*.spec.ts`) picks up Playwright specs** and chokes on Playwright's `test()`. Fixed by `frontend/vitest.config.ts`excluding`e2e/`.
4. **BuildKit doesn't expand ARG in `COPY --from=`** — even with ARG redeclared in the runtime stage. Use a named stage (`FROM oven/bun:${BUN_VERSION}-distroless AS bun-runtime`) instead.
5. **Distroless images have no `wget`** — `docker exec wget` for an air-gapped probe fails. Switched to log-grep probe from outside the container.
6. **`duckdb-async` + Bun race during shutdown**, emitting a SIGTRAP _after_ the test passes. Workaround: `process.exit(0)` before `db.close()`.
7. **The `bun.lockb*` glob in the original Dockerfile matched nothing** because Bun has migrated to text-format `bun.lock`. The wildcard hid the failure until `bun install --frozen-lockfile` ran without a lockfile.
8. **`COPY . .` without a `.dockerignore`** brought the host's `node_modules` on top of the freshly-installed one inside the builder. Different symlink layouts → directory-replacing-file errors.

Each of these has a passing test or a CI gate now. None should re-surface.
